# usage

A macOS menu bar / TUI usage monitor. Reads Claude Code and Codex usage from local files; Antigravity quota comes from Google's official quota endpoint.

## Commands

Run the full set before pushing; CI (`.github/workflows/check.yml`) runs the same, and its Windows job is why mypy runs twice.

- Setup: `uv sync --frozen --group dev`
- Lint: `uv run ruff check .` and `uv run ruff format --check .`
- Typecheck: `uv run mypy .` and `uv run mypy . --platform win32` — both include `tests/`
- Tests: `uv run pytest`; one file: `uv run pytest tests/test_x.py`
- Repo checks: `uv run python scripts/check_doc_parity.py`, `uv run python scripts/build_site_pages.py --check`, `uv run python scripts/check_file_size.py`
- After changing a hook or what it writes: `uv run python scripts/check_upstream.py`

## Gotchas

- Claude usage is written atomically to `~/.claude/usage-status.json` by the statusLine hook. Read order: that file, the legacy `usag-status.json`, the migration-only `tt-status.json`, and finally `cachedUsageUtilization` in `~/.claude.json`. If neither Claude Code source is usable, `loaders/claude_desktop.py` reads the desktop app's `plan-usage-history.json` without credentials or network access. `loaders/chromium_cache.py` can supply exact reset times from the same desktop profile's local HTTP cache when the organization and response age match. It reads both Chromium backends: block-file (`index` + `data_N`) and simple-cache (24-byte placeholder `index`, one `<hash>_0` file per entry; current macOS Desktop), the latter scanned by mtime because entry names hash keys that carry query strings. A Desktop observation newer than a hook reading at least two minutes old replaces the hook only when its organization equals `oauthAccount.organizationUuid` in `~/.claude.json` (`_newer_desktop_snapshot`, used by both the app and `adapters/rate_limits.py`). Newer cached observations replace throttled history samples; older cached windows must match the observed percentages. Missing or unusable cache keeps resets unknown (`None`); never fabricate them or merge windows across organizations. Cache reads are bounded and read-only; Windows opens share read/write/delete access. Never read or decrypt desktop credentials to query quota. Tests isolate desktop discovery with `_isolate_desktop_quota`. `usag-*` may be read for migration only — never written again.
- Codex has no usage hook. `loaders/codex_loader.py` reads `~/.codex/sessions/**/*.jsonl` and `~/.codex/archived_sessions/`, and opens two SQLite files read-only: `state_5.sqlite` for the thread→model mapping and `logs_2.sqlite` for rate limits. `logs_2.sqlite`'s token-entries query (`target = 'codex_otel.trace_safe'`) is legacy-only — current Codex CLI no longer writes those rows (verified 2026-08-10, zero gap vs. jsonl); it's kept for users still holding old-format history. Both go through `_readonly_sqlite_uri()` — `mode=ro` is not optional, Codex may be writing to them. (Codex does have a session hook at `~/.codex/hooks.json`; `installer/session_hooks.py` uses it for resume, not for usage.)
- Antigravity quota has no local file. `loaders/agy_quota_probe.py` first runs `agy -p /usage --output-format json` (no model call; the only source of the Gemini weekly window); if that fails it reads the Antigravity CLI's own OAuth credential, exchanges it for an access token, and queries Google's quota endpoint; `loaders/agy_loader.py` parses local conversations for token counts. Do not describe the project as "never touches the network".
- Tests must never touch the real `~/.claude/` or `~/.codex/`; override the path constants with `monkeypatch`. A test that feeds a disk cache a corrupt file must also `monkeypatch` `cache_quarantine.QUARANTINE_DIR`, or it writes into the real `~/.usage/quarantine/`.
- The autouse `_isolate_log_dir` fixture in `tests/conftest.py` points `usage_logging.LOG_DIR` at `tmp_path`. Do not remove it. `main.main()` calls `_setup_logging()`, so any test that exercises it attaches a `RotatingFileHandler` to the root logger; without the fixture that handler targets the user's real `~/Library/Logs/usage/usage-app.log` and every later test writes into it.
- A disk cache file that fails to decode or parse is moved to `~/.usage/quarantine/` by `loaders/cache_quarantine.py` before the caller deletes it, keeping the evidence for diagnosis. A stale `schema_version` is not quarantined — that is a normal upgrade, and quarantining it would flush the directory's 10-file budget on every version bump.
- When `installer/setup_hook.py` installs or removes the hook, any existing statusLine is backed up under `settings["usage"]["previousStatusLine"]`. Do not change this to overwrite it away.
- Every script in `usage_hooks/` runs outside the venv under macOS `/usr/bin/python3` 3.9. They must stay stdlib-only and use `timezone.utc`, never `datetime.UTC`.
- Every user-visible string goes through `_t()` from `i18n.json`, or `t()` in HTML. `tests/test_i18n_key_parity.py` fails unless a new key is in all five languages.
- The PyObjC mypy ignores in `menubar/app.py` are deliberate; put new feature logic in a leaf module. `scripts/check_file_size.py` enforces the ceilings — lower one after a split, never raise it to get CI green.
- `menubar/state.py` must stay PyObjC-free. `panels` and `menubar.agy` are imported inside functions; a top-level import must never pull in `objc`.
- A panel measures its own height in `panels/dynamic_height.py`, which pins zero-basis `flex: 1` cards to `flex: 0 0 auto` while it measures; the comment above `stretchers` there explains how WIN95 and Newspaper lost their project rows without it. Keep that pin, and do not remove a panel's `overflow: hidden` to work around a clipping report — it is the retro chrome.
- `installer/session_hooks.py` may depend on `installer/setup_hook.py`, never the reverse.
- Burn rate excludes `cache_read_tokens`. Counting them lets a resent context mark heavy users as Heavy indefinitely.
- The price table is downloaded only from `https://raw.githubusercontent.com/BerriAI/litellm/main/model_prices_and_context_window.json` and cached in `~/.usage/pricing_cache.json` for 7 days. A fallback retries after 10 minutes; the old `~/.claude/pricing_cache.json` is read-only.
- Service status reads only Claude Code / Claude API and Codex API, from the `components.json` and `incidents.json` URLs pinned in `usage_common/service_status.py` (`CLAUDE_STATUS` / `CODEX_STATUS`); incidents are fetched only when a watched component is abnormal. Never switch to `summary.json` or `incidents/unresolved.json` — the comment above `CLAUDE_STATUS` and the docstrings in `tests/test_service_status.py` explain why. Never switch to the overall indicator, OpenAI's shared components, or `Codex Web` / `Codex in ChatGPT Desktop` either — all cause false alarms.
- Public docs default to English, with Traditional Chinese as `.zh-TW.md`. README also has `zh-CN`, `ja`, and `ko`, which CI does not enforce — sync them by hand when README changes. `scripts/check_doc_parity.py` only checks English ↔ Traditional Chinese.
- Everything user-visible and everything on disk uses the `usage` prefix, including `com.lollapalooza.usage`. `usag-*` exists only for reading older installs.
- The build script renames `dist/main.app` to `dist/usage.app`. That is expected.
